# Извлечение эмбеддингов COMBVD на сервере (A100)

Инструкция по прогону полного COMBVD на зоопарке моделей. Каждая модель
запускается отдельно — у них разные venv.

---

## 0. Что уже сделано и что нужно посчитать

Картинки **уже отрендерены** (`data/colors/combvd/<датасет>/*.png`), заново
генерировать не нужно. Не хватает только эмбеддингов.

| | Манселл (1755) | COMBVD |
|---|---|---|
| qwen2.5_3B, InternVL3-2B/8B/14B, Phi-4 | есть (`describe_color`) | **нужно посчитать** |
| qwen2.5_7B | есть (`munsell_colors_describe`) | есть только `leeds`, и другим промптом |

Промпт везде один — **`"Describe the color."`**; конфиги `describe_color` и
`munsell_colors_describe` совпадают, так что Манселл переснимать не нужно.

⚠️ Существующие leeds-эмбеддинги qwen-7B сняты промптом `human_like` и в новый
прогон **не годятся**: иначе различие промптов смешается с различием моделей.
Они пишутся в отдельную папку и не перетираются — старые результаты статьи
остаются воспроизводимыми.

## 1. Аудит носителя (один раз, CPU, ~10 секунд)

```bash
python scripts/audit_combvd_gamut.py
```

Отсеиваются пары по двум независимым причинам — обе возникают при рендере
патча в `scripts/generate_combvd_pictures.py`:

**Гамут** (строка 55, `np.clip(lin_rgb, 0, 1)`). Цвет вне охвата sRGB
обрезается, расстояние в паре искажается систематически, сильнее всего
у насыщенных цветов — то есть ровно на той оси, где у отображения основной
выигрыш над CAM16. Пара выбрасывается, если вне гамута хотя бы один цвет.

**Разрешение 8 бит** (строка 136, `np.round(srgb * 255)`). Пара, различающаяся
менее чем на 2 кодовых значения, физически не представима на носителе:
при разнице в 1 к.з. ошибка квантования ±0.5 к.з. даёт ±50% от самой разницы,
при 0 — картинки побитово идентичны и расстояние между эмбеддингами строго
нулевое. Порог задаётся `--min-drgb8` (по умолчанию 2).

| датасет | пар всего | −гамут | −разрешение | осталось пар | цветов к расчёту |
|---|---|---|---|---|---|
| leeds | 307 | 0 | 16 | 291 | 454 |
| rit-dupont | 312 | 28 | 10 | 274 | 415 |
| witt | 418 | 2 | 76 | 340 | 446 |
| bfd_p-d65 | 2028 | 204 | 279 | 1545 | 1935 |
| bfd_p-m | 548 | 192 | 10 | 346 | 359 |
| **ИТОГО** | **3613** | **426** | **391** | **2796** | **3609** |

Создаёт три файла — их и читают все последующие скрипты:

- `data/combvd_pairs_clean.csv` — отфильтрованная таблица пар (+ колонка `drgb8`)
- `data/colors/combvd/keep_colors.json` — индексы цветов, которые надо прогонять
- `data/analysis/combvd_audit.json` — числа для статьи

**`bfd_p-c` исключён целиком** (константа `EXCLUDED` в скрипте): медиана различия
пар там ΔE₀₀ = 0.42, набор почти полностью лежит ниже разрешения носителя —
после фильтров от 200 пар осталось бы 76. Статистика по нему всё равно
считается и пишется в `combvd_audit.json` (поле `excluded_datasets`) — ею
обосновывается исключение в Методах.

⚠️ Leeds после фильтра — 291 пара вместо 307, поэтому **новые числа по Leeds
не совпадут с текущими 0.227/0.238**: изменились и выборка, и промпт. Это
ожидаемо, старые числа заменяются новыми целиком.

## 2. Прогон одной модели

```bash
# активировать venv нужной модели
source ~/venvs/qwen25vl/bin/activate

cd /path/to/Color-MMLs
python scripts/extract_combvd_embeddings.py --config configs/combvd_qwen_2.5_7B.json
```

### Gemma 3 — отдельно

У Gemma **нет ни одного эмбеддинга**, в отличие от остального зоопарка: нужно
прогнать и Манселл, и COMBVD, то есть 1755 + 3609 = **5364 цвета на модель**.

```bash
python scripts/extract_munsell_embeddings.py --config configs/describe_gemma3_12B.json
python scripts/extract_combvd_embeddings.py  --config configs/combvd_gemma3_12B.json
```

Зачем она нужна помимо расширения выборки: в Gemma 3 зрительная башня
(SigLIP-400M) **одна и та же у 4B, 12B и 27B и заморожена при обучении**. Значит
`vision_pooled_mean` у этих размеров обязан совпадать, и получается контрольный
эксперимент под главный тезис статьи: зрительный вход зафиксирован по
построению, поэтому любое расхождение по слою LM изолирует вклад именно
языкового декодера. Ни Qwen, ни InternVL такого контроля не дают — там при смене
размера меняются обе части сразу.

Побочная проверка протокола: если STRESS по VL у 4B и 12B разойдётся заметно,
это признак ошибки в пайплайне, а не свойство моделей.

Вход Gemma 3 — 896×896 против наших патчей 224×224. Для однородной заливки
апскейл точно без потерь (все пиксели одного значения), расхождения
с Qwen/InternVL это не создаёт.

⚠️ Экстрактор Gemma до этого никогда не запускался: в
`utils/embeddings/embedding_extractor_google.py` был закомментирован импорт
класса модели, из-за чего файл падал с `NameError` ещё до загрузки весов.
Починено, но **на живой модели не проверено** — первый запуск обязательно
с `--limit 5`.

### Обязательно: проверить план до запуска

```bash
python scripts/extract_combvd_embeddings.py --config configs/combvd_phi4.json --dry-run
```

`--dry-run` печатает, сколько цветов уже готово и сколько осталось, **не загружая
модель** — работает и без GPU-окружения.

### Полезные флаги

```bash
--datasets witt rit-dupont   # только указанные датасеты
--device cuda:1              # переопределить GPU из конфига
--limit 5                    # первые N цветов на датасет — проверка перед полным прогоном
--overwrite                  # пересчитать уже посчитанное
```

Перед многочасовым прогоном стоит убедиться, что модель вообще поднимается:

```bash
python scripts/extract_combvd_embeddings.py --config <конфиг> --limit 5
```

### Возобновление после падения

Скрипт пропускает цвета, у которых на диске уже лежат все три `.npy`. После
падения, OOM или таймаута просто **повторите ту же команду** — посчитанное
не пересчитывается. Ошибки отдельных цветов не валят прогон: они собираются
в `_run_log.json` и выводятся в конце, код возврата 1.

### Фоновый запуск

```bash
nohup python scripts/extract_combvd_embeddings.py \
      --config configs/combvd_InternVL3_14B.json \
      > logs/combvd_internvl3_14b.log 2>&1 &

tail -f logs/combvd_internvl3_14b.log
```

## 3. Порядок и оценка времени

3609 цветов на модель (после отсева по гамуту и разрешению и исключения
`bfd_p-c`; без фильтров было бы 4767). Ориентир по времени на A100 — уточнится
после первого прогона, фактическая скорость пишется в `_run_log.json`,
поле `sec_per_color`:

| Модель | ≈ с/цвет | ≈ на прогон |
|---|---|---|
| InternVL3-2B, qwen 3B, Gemma 3 4B | 0.1–0.2 | 10–15 мин |
| qwen 7B, InternVL3-8B, Phi-4 | 0.2–0.3 | 15–25 мин |
| InternVL3-14B, Gemma 3 12B | 0.3–0.5 | 25–35 мин |

Суммарно порядка 2–3 GPU-часов на шесть исходных моделей; Gemma 3 добавляет
ещё около часа (у неё считается и Манселл — 5364 цвета вместо 3609).

Память под веса в bf16 — что влезает на A100:

| модель | вес | 40 ГБ | 80 ГБ |
|---|---|---|---|
| Gemma 3 4B | ~8 ГБ | да | да |
| Gemma 3 12B | ~24 ГБ | да | да |
| Gemma 3 27B | ~54 ГБ | нет | да |
| Gemma 4 12B | ~24 ГБ | да | да |
| Gemma 4 26B-A4B | ~52 ГБ | нет | да |
| Gemma 4 31B | ~62 ГБ | нет | впритык |

⚠️ `gemma-4-26B-A4B` — не 4-миллиардная модель: «A4B» это 4B *активных*
параметров на токен, но все 26B экспертов держатся в VRAM. По памяти она
не легче 27B-денса.

Рекомендуемый порядок: **сначала qwen2.5_7B** — на нём построены все текущие
результаты статьи, и он сразу даёт сравнение нового прогона со старым Leeds.
Дальше — от мелких моделей к крупным.

## 4. Проверка результата

```bash
python scripts/extract_combvd_embeddings.py --config <конфиг> --dry-run
```

В колонке «к расчёту» должны быть нули по всем датасетам. Дополнительно:

```bash
cat data/embeddings/<модель>/combvd/describe_color/_run_log.json
```

Поле `failed` должно быть пустым.

Структура результата — по одной папке на цвет:

```
data/embeddings/<модель>/combvd/describe_color/<датасет>/<индекс>/
    vision_pooled_mean.npy       # после визуального энкодера
    projected_pooled_mean.npy    # после адаптера
    lm_pooled_mean.npy           # последний слой языкового декодера
    manifest.json                # xyz, xyY, srgb, rgb_255, промпт, ответ модели
```

Индекс цвета совпадает с колонками `i`/`j` в `data/combvd_pairs_clean.csv`.

## 5. Что дальше

После прогона зоопарка:

1. `utils/analyze/stress_protocol.py` — единый протокол STRESS (групповые сплиты
   по цветовым центрам, per-group k, F-критерий Мелгосы). Через него должны
   проходить и обученные отображения, и аналитические бейзлайны.
2. `scripts/train_maps_full.py` — обучение на полном COMBVD, свип m,
   leave-one-dataset-out, кросс-датасетная генерализация.
3. `python scripts/collect_article_numbers.py` — пересборка реестра чисел.

⚠️ **RIT-DuPont** — набор постоянной воспринимаемой разницы: у всех 312 пар
ΔV = 1.02, потому что каждая пара подгонялась до одного и того же уровня
различимости (T50, пробит-анализ; Berns et al., 1991). По устройству он
совпадает с цепочками Манселла: значима не величина, а **направление** вектора
пары. В групповом лоссе его правильно брать отдельной группой с целью 1,
а не как датасет с калибруемым k.
